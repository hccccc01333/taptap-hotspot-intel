P0 目标：把"能通过程序校验、成功入库，但业务事实不可靠"的成果拦在"可直接使用"之外。不新增 Agent；不调用模型；旧实验记录与冻结代码不变。

按评审给出的验收标准实现并逐条核对：

1. 《明日方舟》参与路径错误（C 组素材把"话题→活动专题页→参与活动"简化成"带话题发帖即可"）——**已能检出**；

## 实现：`agent_v3/claim_verifier.py`

确定性检查，只做词面核对，不做语义判断，不调用模型：

| 检查 | 内容 | 命中判为 |
| --- | --- | --- |
| 断言片段覆盖 | 情报 `observed_change` 按句拆分，每句须在所选引文中被覆盖（相似度阈值，短句更严） | insufficient |
| 具体细节溯源 | 日期、时间、数量（65+／2451 等）、话题标签、书名号名称、奖品名必须出现在所引引文或来源标题中（跨空格/全角归一） | insufficient |
| 参与规则细节 | 含参与/报名/截止/步骤/入口/专题等的断言必须有正文级引文（仅标题级引文不够） | insufficient |
| 参与方式完足性 | "X即可参与/只需X"类断言须有引文逐字支持相同机制 | insufficient |
| 事实位占位 | `截止X月X日`、`#游戏名SideStory#` 等未填槽位 | insufficient |
| 已声明处置位 | `{{TapTap承接链接}}`、待替换/待确认（制作前提，非证据问题） | draft |
| 悬空承接 | 末尾的 `→` 无目标 | draft |

三档状态：`supported` → `draft` → `insufficient`。insufficient 的素材仍写入数据库（保留草稿、可溯源），但被排除在可用素材库之外；信号与创意在 payload 中携带 `evidence_review`（状态+原因码+版本+核对时间），公开导出沿用字段白名单同步该字段。

## 已知边界（不宣称超过）

- 确定性校验不等于语义事实核查：改写式错误（把多步路径换成单步但不含即可类断言）、普通名词/赛季名的张冠李戴、创意 `timing` 字段的日期、标题本身的一般性表述，当前不拦或只标 draft；评审中提到的"独立审核模型辅助"未启用，模型判定也不能当事实真值。
- `insufficient` 只影响"可直接使用"：记录保留为草稿，人工仍可在数据库中核对该记录与来源；草稿复核界面未做。
- 未重跑任何实验；旧结果、旧素材（无 verdict）与已发布文档不追改。
