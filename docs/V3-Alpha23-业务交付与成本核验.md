# Alpha23：业务契约、输入复用与交付验收

日期：2026-10-11。版本：3.0.0-alpha.23。本文记录工程修复与开发回归；旧调试事件不算新的效果验证。

## P0 交付契约

主Agent提交前明确收到业务数组约束：game_signals最多3条，每条basis_refs最多3个、不可重复；fact_refs最多4个。建议每条只陈述一个变化，优先选1至2条最直接的引用。所有注册任务还根据实际Schema动态生成每个数组的数量与重复限制，包括负面素材数组必须为空的规则。

错误反馈只包含可信Schema中的字段路径、规则、实际数量、上限/下限和去重数量，不回显模型数组、来源正文、额外模型字段名或私有推理。一次不合格时在原有两次交付、共享时间预算内重新选择证据并收窄断言。没有放宽引用数，没有截断模型已提交的引用数组；两次仍不合格就不保存业务成果。

Xbox与R6从原实验隔离库复制同一份已保存ready解读，调用真实主Agent业务阶段，继续执行引用、时效、风险、版本和原子入库校验。Xbox精简输入实际保存2条游戏情报，区分未来测试计划与客户端功能变化，影响与玩家需求保持假设。R6精简输入实际保存1条risk_monitoring情报：未来2027年1月15日停运而非已停运，移动平台，负面/中风险；实际素材0、创意0。推广分支受到业务Schema与持久校验共同限制。

这是复用解读的业务回归，不是两条全新事件从采集到创意的验收，也不证明所有引用在语义上正确。核查背景报道：[Xbox](https://www.gcores.com/articles/220709)、[R6](https://www.3dmgame.com/news/202610/3955904.html)。

## P1 输入与成本

业务阶段读取已保存解读的事实、背景、时间线、观点、缺口、时间/风险及来源身份；把重复事实引文转换为同一quote_candidates引用，来源body只提供必要的逐字片段。转换前检查摘要中的引文确实存在于原来源，不改写或丢弃事实。业务模型缺全文时提出具体research_questions，由既有研究流程补查。

模型输入不重复携带全文、所有reading_metadata、事件跟踪缓存与整份图谱。原始来源、解读和图版本仍保留在运行守卫中，事务提交仍会拒绝来源/图/解读/配置版本变化。图谱增强主计划和研究，业务阶段不会因图谱稀疏强制补关系。游戏情报作为基本交付，素材与创意分别判断是否适用。

同一版本、同一已保存解读的完整/精简业务输入：

- Xbox：输入12850→6916 token；输出1310→2009；总计14160→8925，下降37.0%。两组均保存2条情报，一次请求，Schema失败0。完整41.109秒、精简61.922秒，输入更少不意味着耗时更短。
- R6完整：输入16071、输出788、总16859，35.266秒，1条风险情报，素材/创意0。
- R6精简首次请求10.531秒后异常，用量未知，整批按协议停止，业务交付0。不能删除这个失败或把未知用量算0。
- 单独限额恢复检查：第一次授权的token上限不足以容纳单次保守预留，在请求前拦截，实际请求0；另建充分预留的新记录后只调用1次，R6精简输入7965、输出549、总8514，15.719秒，保存1条风险情报、素材/创意0。两次尝试原文件均保留。

仅比较成功且已知用量的业务请求，总31019→17439，下降43.8%；该数不包括精简输入那次未知请求，不能称为真实整批总成本或总体成功率保持。严格包含请求异常的成功率为完整2/2、精简2/3；样本太少且存在恢复检查选择偏差。30%是优化目标，本轮有Xbox单案证据，尚未证明整条链路每条有效情报总体节省30%。价格按Go限时免费边际token统计，不含订阅费，不等于账户账单。

## 全部回归失败保留

首次Alpha23六组开发回归：R6完整链路交付风险情报，Xbox保存ready解读但业务第二次仍超引用上限（4>3），没有业务交付。随后加强明确指令再进行上述业务配对，没有覆盖首批失败。首批研究计划一项请求在工具选择语义校验前已花费token，却未写运行步骤；现已将用量记录移到语义校验前，并增加异常请求记录，避免把耗费漏掉。

## Alpha23交付漏斗

pipeline完成或异常后都保存delivery_funnel，finally仍释放运行租约。漏斗只统计本轮，不把历史情报冒充当前交付：

1. 候选筛选：主Agent选中、留观、归档的路由和原因。
2. 研究取证：证据充分/不足/未完成、复用解读及实际工具失败。
3. 事件解读：ready、Schema失败、时间证据不足、复用次数。
4. 图谱：成功、deferred、exhausted等独立状态；不阻塞有效解读。
5. 业务判断：情报/素材适用说明与增长机会判断分别记录。
6. 持久交付：实际业务记录、game_signal、素材及创意数量，校验拒绝、旧租约/版本拒绝。
7. 质量核验：默认unverified；模型返回、Schema通过、字面引用通过都不会自动改成事实正确。
8. 资源：按阶段输入/输出token、请求秒数、Schema/业务/请求失败及未知用量；工具调用ID、单位、耗时、成本状态可回查tool_execution中的结果与来源。

请求异常日志只存异常类、阶段和耗时，不保存供应商错误正文或推理。用量/价格缺失保留未知。A/B实验资源以请求台账为准，基线不经过生产业务入库；不能拿它的字符串输出数量与game_signal直接比较。
