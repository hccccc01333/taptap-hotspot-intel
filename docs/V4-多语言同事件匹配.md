# V4 多语言同事件匹配（设计 + 可插拔接口）

状态：接口 MVP，未配置真实多语言 embedding 模型；没有用真实跨语言全文对验证。

## 1. 问题

跨语言同事件来源（例如 3DM 中文编译稿 + 英文官方公告）在：
- 标题词重合上几乎为 0；
- 事实引文重合上几乎为 0；
- 只有发布日期可能相近。

当前 `event_match` 的日期/标题/引文规则会把这种来源识别为"元数据候选"
（例如 3DM 全文 + Steam 标题/日期，score 0.35，`metadata_only=true`），但证据强度
不足以合并。只靠日期会误报"同一天同游戏的不同事件"。

## 2. 方案比较

| 方案 | 优点 | 风险/成本 | 建议 |
| --- | --- | --- | --- |
| 本地多语言 embedding（如 bge-m3 / multilingual-e5） | 数据不出本机；可离线批量；可复现 | 需模型文件/内存；阈值需校准 | 首选（若本机资源允许） |
| 经批准的 embedding API | 无需本地模型 | 公开文本会发送给第三方；费用/限流 | 仅公开内容、需明确授权 |
| LLM 翻译后再做词面匹配 | 可读性好、可解释 | 翻译成本/幻觉；不能作为合并依据 | 只做人工辅助 |

## 3. 已实现接口

`context/embedding.py`：

```python
semantic_same_event_candidates(events, facts, embedder, threshold=0.82)
```

- 每个事件用"标题 + 最多 5 条 active 引文"构造文本；
- embedder 由调用方注入（本地模型或 API），返回向量；
- 用 cosine 相似度找候选对，标记 `auto_merge=False`；
- 没有配置 embedder 时不发任何外部请求，`group_match_report` 明确返回
  `semantic_same_event_candidates=[]` 和"未配置"说明。

## 4. 评测计划（未完成）

1. 建一个冻结的跨语言同事件对集合（真实 20–50 对，含难负例：
   同游戏不同事件、同一天不同游戏、标题党改写）；
2. 对候选阈值 0.75/0.80/0.85 报告 precision/recall 与候选数量；
3. 只有 precision 足够高且经过来源核查，才允许把候选进入"待合并"队列；
4. 语义相似只能做候选，不能自动合并、不能替代事实核验。

## 5. 当前证据与限制

- 真实 Steam 全文多次抓取超时，未取得；只有标题/日期元数据候选（0.35）；
- 没有真实多语言 embedding 模型，当前只有假 embedder 的单元测试；
- 日期邻近是启发式，跨语言标题/引文相似度为 0；
- 不经授权不得把内部/敏感文本发给外部 embedding 服务。

## 6. 下一步

选定 embedding 方案（优先本地模型），建冻结跨语言对，按第 4 节评测；在此之前
多语言同事件仍只能输出"元数据候选"，不能合并。
