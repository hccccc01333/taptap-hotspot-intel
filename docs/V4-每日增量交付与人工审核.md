# V4 每日增量交付与人工审核

状态：MVP（2026-11-25，UTC+08）。目标是把已有事件包持续转成共享前端可读的三类型交付，
不自动发布，也不把自动检查当成事实核验或人工批准。

## 每日运行

```powershell
# 1. 采集公开发现流（评论可按预算另开）
python -X utf8 data_source/collectors/taptap/crawl_taptap_discovery.py `
  --source discover --limit 20 --max-pages 2 --empty-pages 2 `
  --max-comment-calls 0 --data-dir data/raw/taptap/daily

# 2. 从已研究事件包做增量交付；--pack-root 可包含多个批次目录
python -X utf8 scripts/v4_daily_delivery.py `
  --discover-csv data/raw/taptap/daily/discovery_posts.csv `
  --pack-root docs_local/evaluations/v4-taptap-recent-20261123/pack-7 `
  --out data/v4/deliveries --state data/v4/daily-state.json `
  --references docs_local/evaluations/v4-taptap-recent-20261123/reference-library.json `
  --days 7 --limit 5

# 3. 导出公开静态数据
python -X utf8 scripts/export_v4_deliveries_public.py
```

当前 runner **不自动研究** `--pack-root` 中不存在的事件。缺失研究包会进入
`data/v4/deliveries/daily-last-run.json` 的 `failed`，并在 state 中累计尝试次数；
研究包补齐后重跑即可继续，不会重复交付已成功事件。单个坏包只记录自己的失败，
不会阻断同批其他候选；`--limit` 限制成功交付数，缺失包不会挤占可交付事件名额。

## 增量规则

- 以 TapTap `moment_id` 为幂等键，不以标题模糊去重；CSV 重复行先去重；
- 默认只选择最近 7 天、正文至少 40 字的新事件，按发布时间倒序；
- 第一次运行会从现有交付索引的回填状态，避免把旧成果再次交付；只有包、预览和
  自动检查都存在且通过才进入成功账本，失败包下次仍会重试；
- `delivered` / `skipped` / `failed` 分列；重复事件跳过原因固定为 `already_delivered`；
- `--limit` 限制成功交付数；最新候选缺包时会继续扫描较旧的可交付候选；
- 新交付合并进原索引，不删除既有交付；
- 失败不会写入成功账本；有失败时 CLI 退出码为 1；
- 打包、每日运行、审核与公开导出使用同一输出目录锁；JSON/HTML 采用唯一临时文件替换。

## 审核状态

| 状态 | 含义 |
| --- | --- |
| `draft` | 自动检查未通过，不能人工通过 |
| `needs_review` | 自动检查通过，但独立事实核验/人工审核待完成 |
| `approved` | 人工填写审核人和理由，且自动检查通过 |

人工审核（本地受控操作，不提供匿名公开写接口）：

```powershell
python -X utf8 scripts/v4_daily_delivery.py `
  --review-event yanyun_tga_nomination --review-status approved `
  --reviewer "运营复核人" --note "已对照公开来源核查提名与五抽表述；未确认领取条件。"
```

- 每次审核追加到 `review_history`，保留最近 50 条；
- 审核记录包含内容哈希；重新生成后内容、稳定证据字段或自动检查变化会使原审核失效；
  旧审核包缺少哈希时也保守地退回 `needs_review`，不会把新内容继承为已批准；
- 审核命令同步更新 `delivery.json`、`preview.html` 和 `index.json`；
- 共享前端显示审核状态、审核人、说明与待处理风险；
- `approved` 只代表人工批准这份草案，不代表已发布或增长效果已验证。

## 边界

- 当前是手动触发的每日流程，没有创建定时任务；
- runner 不采集、不研究、不发布，只负责候选筛选与交付合并；
- 自动检查仍是代理指标；引用逐字存在不等于语义支持；
- 公开静态导出需要单独运行并提交，不是实时同步；
- state 与 `data/v4/` 不提交公开仓库；公开页面只接收脱敏后的交付。
