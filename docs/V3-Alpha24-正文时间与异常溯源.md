# Alpha24：正文边界、时间线证据和请求异常

日期：2026-10-11。版本：3.0.0-alpha.24。针对上一轮质量核验暴露的问题进行开发修复，不重新运行已停止的正式实验，不覆盖其失败结果。

## 这次解决什么

Alpha23新样本中，网页作者`YT17`与“9 小时前”在脱离页面的DOM文本中黏连，模型误写成“179 小时前”。原来只校验recency时间，错误仍可能留在timeline展示。另有请求失败只记录通用异常，无法区分连接超时、读取超时或连接中断。

浏览器现在使用独立的`page_reader.cjs`遍历实际渲染的DOM：为内联元素添加空格，为块元素保留段落；忽略导航标签、脚本、隐藏和导航角色内容，不修改原页面。读取最多20,000个节点，超出即失败，不能把部分结果当成功。机核新闻优先读取实际`.newsPage_content`或`.articlePage_content`区域，避免全页导航进入正文。其他页面仍使用已有正文选择器，找不到时明确标记为可见全页，不能声称取得纯正文或完整全文。截图、公开网络限制和评论区域规则保留。

研究解读增加timeline的交付前校验：非空`time_text`必须逐字出现在**该节点所选引用**中；只有`time_kind=report`允许匹配这些引用所属来源的发布日期元数据。元数据不能证明事件发生日期。失败反馈只有固定字段路径和规则，模型可在原有两次调用及共享时限内重新选择证据或明确时间未知；反复失败不保存无效解读、不进入业务阶段。程序不会静默清空数组或修改错误日期冒充通过。

主、子Agent提示词同时强调断言与所选片段的对应：人物背景、声优、角色数量等应各自选直接片段，不能全部引用开头公告；缺少片段就收窄断言、补查或保留未知。解读和业务版本升至v3.24，自动调度按现有版本规则重新评估，不增加手动操作或新Agent。

模型适配层依据实际Requests异常类型记录白名单类别：`connect_timeout`、`read_timeout`、`connection_error`、`request_exception`；无效接口JSON记`response_json_invalid`。运行步骤及实验请求记录采用相同类别。日志不记录原异常文本、URL参数、密钥、响应正文或私有推理；异常后的用量仍为unknown，预算调用前拒绝仍单独记录，不能计为免费成功请求。旧实验的未知异常不会被倒推成某种超时。

## 验证与边界

新增8项回归覆盖：正文边界及站点区域、隐藏内容和节点预算；四种真实异常类的安全分类、未知用量与私密文本排除；无效JSON；不可信类别过滤；所选引文时间依据；报道与事件日期区分；首次失败后模型重新交付；两次失败不写解读/业务并保留漏斗。CI纳入同一套测试。

517项完整工程回归及独立恢复通过。源码检查点443文件，SHA256 `51371b6888cff3612dd607cb62671414b1eb8a5a08b5dd8e95979b6f2a61aa23`；SQLite完整性、7次历史用量、170个截图/元数据文件核对通过，旧负面创意保留但不能进入可用成果。此验证段在检查点之后追加。本地后端加载Alpha24，8202/5182 HTTP均200，正式模型步骤仍159，本轮新增0。

实际Edge渲染夹具确认作者与时间不黏连、隐藏内容不进入正文、DOM未改变。真实机核旧案例网页返回HTTP200，选定正文区域，作者`YT17`与当前页面“19 小时前”分别成行，正文1,400字符，导航不再出现在开头。相对时间随访问时刻变化，此结果不反推原实验的事件日期。两次开发读取及截图保存在忽略目录，未写入正式成果库。

**引用真实性与断言成立是两种检查。** 本次时间线规则能拦截“时间不在所选引文或对应报道元数据中”，不能证明所有语义推断正确。新增提示词也没有独立质量提升结论。旧截图、正文缓存、已保存解读和冻结实验保留；缓存按原重试窗口刷新，不把历史结果改成成功。没有调用真实模型验证新提示词，不宣称修复了所有语义引用错误。
