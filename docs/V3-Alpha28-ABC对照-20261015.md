# Alpha28 A/B/C 对照：Agent 架构增量价值测量 / 2026-10-15

按用户选定方案执行：同一批 10 个事件、同一模型（LongCat 2.5 Preview Free）、三组对照——A 纯 LLM 直接报告、B LLM＋搜索、C 真实完整链路（主/研究 Agent、工具、解读、图谱、门禁与持久交付）。衡量有效事实覆盖、错误内容放行率、成功交付率；成本单独报告，不参与质量评分。

**本轮结论：C 未在事实覆盖与错误放行率上优于 B——不构成"完整 Agent 优于 LLM＋搜索"的技术优势证据；C 唯一领先项是交付率。** 按用户既定判断标准，这属"增量价值尚未证明"，不是 Alpha27 的失败。

## 方法与冻结

- 10 个未用事件（8 游戏更新 + 1 发布会汇总 + 1 负面爆料），每案 2 项必要事实运行前固定；manifest `874d0a8c…`，gold `c61f90fc…`，30 组（10×A/B/C）。
- 前置：模型行为预检通过（17.3 秒正常结束）、传输双窗口 6/6；失败不重跑、单例停止语义。
- A/B 由基准实现单次调用产出结构化报告（claims＋citations）；C 由完整链路产出同类报告（`project_full` 与基准报告结构刻意对齐）。评测：事实覆盖＝报告文本＋引文中可见；错误放行率＝对 fact/date/product 断言做确定性词面核对（引用缺失/片段不覆盖/否定冲突计为不支持）；成本取账本分列。

## 判读（含测量口径的重要限定）

1. **交付可靠性 C 领先**（0.90 对 B 0.80、A 0.70）：完整链路的结构化契约与重试让交付更稳定。
2. **事实覆盖 B 领先**（16 对 C 15；仅交付案例 100% 对 83%）：B 的"一次搜索＋一次写作"直接面对素材，引用更贴事实；C 的研究→包→业务多级转手存在信息损耗——与本项目此前批次观察一致（业务阶段只能看到研究所选引文）。
3. **错误放行率 B 最低（44%）、C 最高（58%）——但此口径需要限定**：C 产出 65 条可核对断言（A/B 为 35/43），断言更长、更丰富，确定性词面核对对标量更长的文本更严格；且 **A/B 没有任何门禁**（不支持断言直接随报告交付），C 的 38 条不支持断言中，业务记录部分被门禁降为草稿、不进入可用成果。因此"报告层放行率"与"可用成果层放行率"不是同一件事，本表是前者；后者的严格口径需要以门禁后内容为分母重算（列为本轮已知缺口）。
4. **成本差异巨大**：C 的调用数 5.7×、token 约 7×于基线——按用户要求单独报告，不参与评分；但它是 C 需要拿出增量的理由。

## 统一口径重算（补充，2026-10-15 深夜）

按报告"已知缺口"项，对既有冻结数据做了两层口径重算与逐事实归因（只读，零新模型调用；`re-measure.json`）：

| 可用成果层事实可见（/20） | — | — | 12 |

- **C 的架构价值在统一口径下首次以数字显现**：过门禁进入可用成果的断言 13 条全部有引用支持（0% 放行错误），而 A/B 没有门禁、不支持断言随报告直接交付。C 的"高报告层错误率"很大程度上是门禁把问题挡在草稿区的**累计暴露**，不是放行质量差。

## 已知限定与下一步选项

- 单轮 10 事件 × 3 组是工程规模，非统计显著性；模型当日的波动（3 例失败/停止）三组共担但影响不等。
- "错误放行率"当前为词面核对口径；下一轮应改为"门禁后可用成果"为分母的统一口径，并对 A/B 报告同样应用同一核查器后再比。
- 若要让对照更有分辨力：加大样本（如 20–30 事件）、降低共同模式噪声（更稳定的模型/网络）、或给 C 增加"研究引文保真"的针对性改进（上一轮已实施核心事实规则与门禁反馈重试，本轮 C 的覆盖 0.833 已高于 Alpha27 六批的逐产出案例 63–75%）。

## 图谱优化与默认关闭（2026-10-19，用户裁定：先优化、仍不行则默认关闭）

**优化内容（本次实施，全部有测试钉死）**：

1. **自门控（engagement gate）**：图谱只在"库内存在其他已解读事件"时才做检索增强、图谱提示与抽取调用。单事件库（基准的隔离试次、冷启动）中图谱没有可关联的内容，自门控下跳过检索、提示与抽取——不再为不可能产生增量的事实支付一次调用与一个失败点。判定谓词 `graph_retrieval.engaged()`（同时受总开关约束）；基准/实验需要测量图谱变体时用 `V3_GRAPH_FORCE=1` 显式越过该门控。
2. **总开关默认改为关闭**：`V3_GRAPH_MODE` 缺省即 off（原先默认 on）。C 臂在基准运行器内显式 `on + FORCE` 以保留测量能力；生产默认不再图纸谱成本。
3. **保留既有失败隔离**：抽取异常只降级图谱状态（deferred/exhausted），不拖垮已核实解读；配合自门控，单事件场景下该失败点也不再出现。

**验证**：新增门控回归（单事件库 engaged=false、`graph_context.mode=isolated`、抽取零调用且保留 pending）；全量 446 项测试通过；真实模型冒烟（单事件库、`V3_GRAPH_MODE=on`、不 FORCE）：解读正常交付，`graph_extraction.status=not_applicable`，账本零 `graph_extraction` 调用（业务阶段另因窗口缺陷 deferred，与图谱无关）。

**"仍不行"的证据（决定默认关闭的依据）**：

- 两批四臂对照（28d 合并数）：C 交付 4/20 vs C0 10/20、覆盖 7 vs 12，方向两批一致；既有的两轮审计 20 试验中图谱检索源 0 次被交付引用，图谱占 C 成本 6.4%/7.7%（早期口径 20.3%）。
- **生产库图谱实际内容近乎为空**：`kg_entity` 33、`kg_claim` 25、`kg_need` 0、`kg_community` 0（AI 暂停后抽取未积累）。即使开启，社区层与邻域检索也基本无内容可供交付。
- 基准的"每试次单事件隔离库"使图谱在结构上无法产生跨事件增量——C-vs-C0 在该装置里只能测到图谱的成本与脆弱性，测不到其价值。

**裁定**：按用户指示，图谱**默认关闭**（保代码、保开关、保 C0 臂）。重新启用条件与方式：图谱在多事件生产库中积累出可用内容（成交付引用的图谱源 >0、社区可用）后，设置 `V3_GRAPH_MODE=on` 即可恢复；基准实验中仍以 `on+FORCE` 运行 C 臂。若未来要证明图谱价值，应设计**多事件 populated-store** 实验（同游戏/同系列事件群，图检索确有邻域可选时测量覆盖与引用增量），而非单事件四臂对照。

## 解读证据反馈软化：终次确定性剔除（2026-10-19）

**背景**：Alpha28d/28e 两批中，解读阶段的"首拒→重试→再拒即整组失败"链条合计损失约 9 组 C/C0 试次（2532-C、2532-C0、e6e6-C0、356b-C、f508-C、d6ed-C0、28e 的 1-C、2-C 等）。免费模型对证据反馈的自纠能力有限，重试常以 schema 缺字段或换一类无据断言收场，而失败代价是整条事件无任何可用产出。

**新语义（按用户"降为警示"裁定实施）**：

- **首次交付**：保留有界反馈（时间轴规则与引文核对各一次），措辞不变。
- **终次交付**：不再整组失败，改为**确定性修复**——逐条复算：无引文支持的 `background`/`core`/`controversies` 条目与时间轴条目（`time_basis_missing`）直接剔除，其余核验通过的内容照常交付；剔除原因写入 `interpretation_repair` 审计步骤。**无据文本绝不进入交付**，零错误放行不变量由"剔除"而非"整组拒绝"维持。
- `views` 不按逐字覆盖率剔除（观点摘要本就不是原句复述），其完整性仍由既有"actual_comment 必须引用有效评论样本"的溯源硬规则把关（该规则保持 ValueError 硬拦）。
- 业务阶段反馈同步有界化：终次交付不再因引用核对二次失败而抛错（信号/素材仍逐条过门禁）。

**验证**：新增/更新回归——无据 background 条目终次剔除且交付、无据时间轴条目终次剔除且不落库、覆盖但错标的 actual_comment 仍被溯源规则拒绝、重试后业务照常；全量 448 项通过。真实模型冒烟（生产默认：图谱关闭）：首试 4 条无据断言触发反馈 → 重试 → `interpretation_repair` 剔除 `background/0` 并成功保存解读——同一形态在旧语义下会整组失败。

**限定**：剔除会减少可交付的研究条目（以质量换交付存活）；被剔除的断言若确为事实，只能由后续批次的重新研究补回。解读层不参与可用成果层的 0% 错误放行统计，但公开展示的解读文本同样只含已核验条目。
