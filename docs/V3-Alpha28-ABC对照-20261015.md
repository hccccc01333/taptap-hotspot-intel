# Alpha28 A/B/C 对照：Agent 架构增量价值测量 / 2026-10-15

按用户选定方案执行：同一批 10 个事件、同一模型（LongCat 2.5 Preview Free）、三组对照——A 纯 LLM 直接报告、B LLM＋搜索、C 真实完整链路（主/研究 Agent、工具、解读、图谱、门禁与持久交付）。衡量有效事实覆盖、错误内容放行率、成功交付率；成本单独报告，不参与质量评分。

**本轮结论：C 未在事实覆盖与错误放行率上优于 B——不构成"完整 Agent 优于 LLM＋搜索"的技术优势证据；C 唯一领先项是交付率。** 按用户既定判断标准，这属"增量价值尚未证明"，不是 Alpha27 的失败。

## 方法与冻结

- 10 个未用事件（8 游戏更新 + 1 发布会汇总 + 1 负面爆料），每案 2 项必要事实运行前固定；manifest `874d0a8c…`，gold `c61f90fc…`，30 组（10×A/B/C）。
- 前置：模型行为预检通过（17.3 秒正常结束）、传输双窗口 6/6；失败不重跑、单例停止语义。
- A/B 由基准实现单次调用产出结构化报告（claims＋citations）；C 由完整链路产出同类报告（`project_full` 与基准报告结构刻意对齐）。评测：事实覆盖＝报告文本＋引文中可见；错误放行率＝对 fact/date/product 断言做确定性词面核对（引用缺失/片段不覆盖/否定冲突计为不支持）；成本取账本分列。

30 组全部执行完毕：23 返回、3 失败、3 单例停止、1 部分（三组共用同一批事件与同样的传输环境）。

| 指标 | A 纯 LLM | B LLM＋搜索 | C 完整 Agent |
| --- | --- | --- | --- |

## 判读（含测量口径的重要限定）

1. **交付可靠性 C 领先**（0.90 对 B 0.80、A 0.70）：完整链路的结构化契约与重试让交付更稳定。
2. **事实覆盖 B 领先**（16 对 C 15；仅交付案例 100% 对 83%）：B 的"一次搜索＋一次写作"直接面对素材，引用更贴事实；C 的研究→包→业务多级转手存在信息损耗——与本项目此前批次观察一致（业务阶段只能看到研究所选引文）。
3. **错误放行率 B 最低（44%）、C 最高（58%）——但此口径需要限定**：C 产出 65 条可核对断言（A/B 为 35/43），断言更长、更丰富，确定性词面核对对标量更长的文本更严格；且 **A/B 没有任何门禁**（不支持断言直接随报告交付），C 的 38 条不支持断言中，业务记录部分被门禁降为草稿、不进入可用成果。因此"报告层放行率"与"可用成果层放行率"不是同一件事，本表是前者；后者的严格口径需要以门禁后内容为分母重算（列为本轮已知缺口）。
4. **成本差异巨大**：C 的调用数 5.7×、token 约 7×于基线——按用户要求单独报告，不参与评分；但它是 C 需要拿出增量的理由。

## 统一口径重算（补充，2026-10-15 深夜）

按报告"已知缺口"项，对既有冻结数据做了两层口径重算与逐事实归因（只读，零新模型调用；`re-measure.json`）：

| 口径 | A | B | C |
| --- | --- | --- | --- |
| 报告层错误放行率（原表） | 0.571 | 0.442 | 0.585 |
| **可用成果层错误放行率**（门禁后 needs_review 内容） | 无门禁 | 无门禁 | **0.000**（13 条断言、0 条不支持） |
| 可用成果层事实可见（/20） | — | — | 12 |

- **C 的架构价值在统一口径下首次以数字显现**：过门禁进入可用成果的断言 13 条全部有引用支持（0% 放行错误），而 A/B 没有门禁、不支持断言随报告直接交付。C 的"高报告层错误率"很大程度上是门禁把问题挡在草稿区的**累计暴露**，不是放行质量差。
- **代价也明确**：门禁后可用断言仅 13 条、可用层事实可见 12/20——安全性与产出量之间是有取舍的。
- **逐事实损失归因**：C 漏掉的 8 个事实中 **5 个丢在研究阶段**（解读未选到对应引文）、3 个丢在可用成果阶段（解读有、业务未带上或降稿）。研究引文保真因此被确认为下一轮的首要改进点（随后已实施 key_fact_hints 清单，见 Alpha28b）。

## Alpha28b 复比（新事件批，环境异常 —— 不作比较结论）

| | A | B | C |
| --- | --- | --- | --- |
| 交付率 | 0.70 | 0.50 | **0.10** |
| 用量未知调用 | 4 | 4 | **9**（C 每例约 38 次调用、A/B 各 10 次） |

**这暴露了对照设计对传输环境的系统性依赖：闪断按调用数惩罚各组——多调用的完整链路（C）在故障窗口中的暴露面积约为基线的 4 倍**，共同模式噪声假设不成立，本批的三组比较无效（同批次3的性质）。已留存全部数据（`alpha28b-*` 实验目录与两层评估文件），不作任何架构结论。

**可用的弱信号（仅记录，不作推断）**：少数完成训练中，（a）研究阶段关键事实仍有个别丢失（key_fact_hints 的效果无法在本批判定，因为绝大部分 C 组死在情报阶段前）；（b）C 在可用成果层的引用纪律保持。**复比（Alpha28c 或同一设计的新批）应在传输稳定窗口执行，建议选北京时段且先跑连续两轮探针全通的预检。**

## Alpha28c 复比（10-15/16 新事件，环境干净，与 Alpha28 合并判读）

Alpha28c（manifest `1b429666…`、gold `0ac07a1d…`、30 组）在传输连续两轮全通的窗口开跑，运行器带熔断冷却（闪断即停跑等待恢复）。**30/30 记录（18 返回、6 失败、4 部分、2 停止），全程仅 2 笔未知用量**（对比 Alpha28b 的 18 笔）——这是两轮对照中最干净的一批执行。

**两轮合并（Alpha28 + Alpha28c，同类设计、同模型、各 10 事件）**：

| 指标 | A 纯 LLM | B LLM＋搜索 | C 完整 Agent |
| --- | --- | --- | --- |
| 成功交付率（两轮） | 0.70 / 0.90 | 0.80 / 0.50 | **0.90 / 0.80** |
| 有效事实覆盖（两轮，/20） | 13 / 13 | 16 / 8 | 15 / 11 |
| 覆盖合并（/40） | 26（65%） | 24（60%） | 26（65%） |
| 错误放行率（报告层，两轮） | 0.571 / 0.542 | 0.442 / 0.556 | 0.585 / 0.700 |
| 错误放行率（可用成果层） | 无门禁 | 无门禁 | **0.000 / 0.000**（两轮共 23 条门禁后断言、0 条不支持） |
| 用量未知调用（两轮） | 1 / 0 | 1 / 1 | 1 / 1 |

**合并判读**：

1. **交付可靠性：C 相对 B 的优势复现**（0.90>0.80 与 0.80>0.50）；相对 A 两轮互有胜负（0.70<0.90、0.90>0.90 平）。第二轮 B 的交付崩到 0.50 为基线报告模式下的模型交付失败（6 失败中占多数），与架构无关的模型侧噪声。
2. **覆盖率：C 未表现稳定优势**。单轮互有胜负（15 vs 16；11 vs 8），合并 C 26 = A 26 > B 24——B 第二轮的交付崩溃拉低了它的合并覆盖。**没有达到"C 在覆盖上优于 B"的判定门槛。**
3. **C 的独特价值在可用成果层纪律上两轮完整复现：门禁后断言 23/23 全部有引用支持（0% 放行错误）**，而 A/B 无门禁、约一半（合并 55%/49%）的不支持断言随报告直接交付。这是"完整 Agent 架构"在两轮对照中唯一稳定、可复现的增量。
4. **key_fact_hints 改进效果未获证明**：第二轮研究阶段流失 9 项（第一轮 5 项），但 C 组本轮 6 失败/4 部分导致只有 8 例可评估，样本被交付失败污染，无法归因到改进本身。诚实结论：**无证据，需干净样本继续**。
5. 成本仍为 C 约 7×（单独报告，不参与评分）。

**复比后的技术优势判定（不变）**：按用户标准（C 需在有效事实覆盖或错误放行率上优于 B），**两轮合并后仍不成立**；C 稳定领先的只有交付率与"可用成果层零放行错误"两项可用性与纪律指标。若继续追平覆盖，方向仍是研究引文保真 + 更大样本（20–30 事件）在稳定窗口执行。

## 图谱价值审计与消融设计（2026-10-16）

对两轮对照的全部 20 个 C 组试验做了零成本取证审计（`budget.sqlite3` 成本 + 运行库存引的 Macht 三表）：

| 项 | 结果 |
| --- | --- |
| 图谱调用与 token | 19 次调用、169,361 token = C 总 token 的 **20.3%**（调用数 17.9%） |
| 图谱检索源进入交付引用 | **0 / 20 试验**（交付的全部 17 个不同引用证据中，无一条来自图谱检索） |
| 图谱索引产出 | 722 实体、313 关系、20 文档——建了但零引用 |
| 图谱交付错误 | 1 次 |

限定：该口径测的是"图谱检索源是否被交付采纳"；模型读入 graph_context/图谱提示后的**隐性影响**无法由此测出。因此按"先测量、再动刀"的原则，**新增图谱消融臂 C0**（`V3_GRAPH_MODE=off`：不跑图谱抽取、不做图谱检索、不加图谱提示，其余链路完全一致；有回归钉死开关行为），下一批对照将为 **A/B/C/C0 四臂 × 10 事件 = 40 组**，一次回答两个问题：图谱的边际价值（C vs C0）与四项优化在干净窗口下的效果（C vs 两轮历史）。

## 已知限定与下一步选项

- 单轮 10 事件 × 3 组是工程规模，非统计显著性；模型当日的波动（3 例失败/停止）三组共担但影响不等。
- "错误放行率"当前为词面核对口径；下一轮应改为"门禁后可用成果"为分母的统一口径，并对 A/B 报告同样应用同一核查器后再比。
- 若要让对照更有分辨力：加大样本（如 20–30 事件）、降低共同模式噪声（更稳定的模型/网络）、或给 C 增加"研究引文保真"的针对性改进（上一轮已实施核心事实规则与门禁反馈重试，本轮 C 的覆盖 0.833 已高于 Alpha27 六批的逐产出案例 63–75%）。
- 原始档案（含三组逐案例结果与账本）在本地 `data/v3/experiments/alpha28-20261015/`；评估器与结果 `abc-results.json`。
