- **部分成功：《月圆之夜》**。C生成3条情报、1条业务素材、1个创意，有叙事切口、文案与脚本；实际仍有占位承接链接和制作前提。附带新种族引文没有包含种族名称，官方身份也未充分验证。A/B能够覆盖未来上线与卡牌数量，未因输出少就判低质量。正文是未来预告，不应标成已经发生的上线。[原帖](https://www.taptap.cn/moment/857941390309460399)。
- **共同缺陷：《明日方舟》**。三组都没覆盖已存在的“话题→活动专题→参与活动”入口。A素材截止时间比原文多1分钟；C把投稿路径改成带话题发帖即可，且奖品、类别、截止等细节只配标题引文。C虽然读到完整规则，仍保存有此错误的模板；创意阶段请求异常，没有交付创意。实际原帖参与规则和截止时间可直接核查。[原帖](https://www.taptap.cn/moment/857212442608928258)。

## 失败与阶段漏斗

20组没有最终报告，另1组C只返回筛选归档记录。大量错误被内部状态记为`budget_stopped`，但具体原因是连接/请求异常；不能据此声称额度耗尽或达到了600秒。C《明日方舟》也是该状态，却已经保存2条情报和1条素材，需要单列部分交付。所有逐组状态、研究充分性、解读ready、图谱、业务判断、实际入库和异常均见机器报告。

完成了网页/模型目录只读连通性检查，不代表推理流式请求稳定。连接异常根因尚未确定，不能把此次服务失败当成模型事实错误，也不能排除它来宣称系统可靠。负面/争议事件全部失败，没有为“没有创意”加风险正确分。

C仅两个事件进入ready解读和业务交付，图谱均成功；其余失败或提前归档不自动算证据不足正确。逐字引用可以在页面找到，仍可能不支持对应断言，尤其是用标题支持规则细节。

## 后续改进的验收点

1. 先定位流式连接失败和安全错误分类；未知用量继续保留，不无限重试，不排除失败样本。
2. 引文必须直接支持对应断言，并逐项核对奖品条件、参与步骤、日期和素材全文；不能只检查Schema与逐字出现。
3. 评论正文未取到就保持未知，禁止由评论数量或工具completed推断态度；不完整字符串与占位承接须明确标草案。
4. 修复后另冻新样本批次，保留本轮全部结果；独立人类复核仍未完成，不继续堆架构证明优势。

本轮没有验证真实TapTap增长效果。两例共享核聚变背景，样本非独立随机；没有通用梗正面转化例子，推论仅限这批事件与当前运行环境。
